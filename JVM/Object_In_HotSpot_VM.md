## Object In HotSpot VirtualMachine 

**📝1.객체 생성 / Object Construction**
1. JVM이 `new` 키워드에 해당하는 바이트코드를 만나면, 이 명령의 매개 변수가 상수 풀 안의 클래스를 가리키는 `Symbol` 참조인지 확인한다.
2. 이 `Symbol`참조가 뜻하는 클래스가 로딩, 해석(resolve), 초기화(initialize)되었는지 확인한다.
3. 준비되지 않은 클래스라면 로딩부터 해야한다. (class loader ???)
4. 로딩이 완료된 클래스라면 새 객체를 담을 메모리를 할당한다. (필요한 메모리의 크기는 클래스를 로딩하고 나면 완벽하게 알 수 있다.)
5. `객체용 메모리 공간 할당은 jvm 힙에서 특정 크기의 메모리 블록을 잘라 주는 일이라 할 수 있다.`
```text
    자바 힙이 완벽히 규칙적이라고 가정하면 사용 중인 메모리는 모두 한쪽에, 여유 메모리는 반대편에 자리하며,
    포인터가 두 영역의 경계인 가운데 지점을 가리키게 될 것이다.
    이 상태에서 메모리를 할당하면 포인터를 여유 공간 쪽으로, 정확히 객체 크키만큼 이동시키게 된다.  
```
6. 이러한 할당 방식을 `포인터 밀치기( bump the pointer )`라고 한다.  

```text
멀티스레딩 환경에서는 여유 메모리의 시작 포인터 위치를 수정하는 일도 스레드 안전하지 않으므로 동시성 문제가 발생할 수 있다.
예컨대 한 스레드가 요청한 객체 A를 위해 메모리를 할당하는 과정에서, 포인터의 값을 아직 수정하기 전에 다른 스레드가 객체 B용 메모리를 요청할 수 있다.
```

**solution**
1. 메모리 할당을 동기화
2. 스레드마다 다른 메모리 공간을 할당: `스레드 각각이 자바 힙 내에 작은 크기의 전용 메모리를 미리 할당받아 놓는 것이다.`
    - 이런 메모리를 `스레드 로컬 할당 버퍼(TLAB: Thread Local Allocation Buffer)`라고 한다.
    - 각 스레드는 로컬 버퍼에서 메모리를 할당 받아 사용하다가 버퍼가 부족해지면 그때 동기화를 해 새로운 버퍼를 할당받는 방식
3. JVM이 스레드 로컬 할당 버퍼를 사용할지는 `-XX:+/-UseTLAB` 매개 변수로 설정한다. ( 일반적인 HotSpot JVM 기준으로 `-XX:+UseTLAB`은 기본적으로 켜져 있다. )
   - 메모리 할당이 끝났다면 JVM은 할당 받은 공간을 0으로 초기화 한다. 
   - Java 코드에서 객체의 인스턴스 필드를 초기화하지 않고도 사용할 수 있는 이유가 이 단계 덕이다.
   - 모든 필드가 자연스럽게 각 데이터 타입에 해당하는 0 값을 가지고 있게 되는 것이다.
4. 다음 순서로 JVM은 `각 객체에 필요한 설정`을 해준다.
   - 어느 클래스의 인스턴스인지, 클래스의 메타 정보는 어떻게 찾는지, GC 세대 나이(age)는 얼마인지 등의 정보
   - 이런 정보가 각 객체의 객체 헤더에 저장된다.


```text
자바 컴파일러는 자바의 new 키워드를 발견하면 바이트코드 명령어인 new와 invokeSpecial로 변환한다
new는 앞서 이야기한 메모리 할당 단계를 수행
invokeSpecial은 방금 이야기한 <init>() 메서드 호출을 담당

<Java 코드>              <바이트 코드>
    new      ------->   new : 자바 가상 머신 관점에서 객체 생성(메모리 할당 등)
              \ 
                \ 
                  ↘     invokeSpecial: 자바 프로그램 관점에서 객체 생성 (생성자 실행)              
```

**📝2.객체의 메모리 레이아웃 / Memory Layout of Object **
- HotSpot JVM은 객체를 세 부분으로 나누어 힙에 저장한다.
  - `객체 헤더`
    - 마크 워드(`mark word`): 객체 자체의 런타임 데이터 (ex. 해시코드, GC세대나이, 락 상태 플래그, 스레드가 점유하고 있는 락들 등등...)
    - 클래스 워드(`klass word`): 객체의 클래스 관련 메타데이터를 가리키는 클래스 포인터 
    - 배열 길이(자바 배열인 경우)
  - `인스턴스 데이터`: 다양한 타입의 필드 관련 내용, 부모 클래스 유무, 부모 클래스에서 정의한 모든 필드가 이 부분에 기록된다.
  - `길이 맞추기용 정렬 패딩 (alignment padding)`: 존재하지 않을 수도 있으며, 특별한 의미 없이 자리를 확보하는 역할만 한다.
    - HotSpot JVM의 자동 메모리 관리 시스템에서 객체의 시작 주소는 반드시 8바이트의 정수배여야 한다. <br/> 
      달리 말하면 모든 객체의 크키가 8바이트의 정수배여야 한다는 뜻이다. <br/>
      객체 헤더는 8바이트의 정수배가 되도록 잘 설계되어 있기 때문에 인스턴스 데이터가 조건을 충족하지 못하는 경우에만 패딩으로 채운다.
